# 导航故障自动保存、查看和导出

导航按原命令启动，无需另开录制终端。每次启动自动创建独立会话，保存在机器狗宿主机
`~/go2_nav/runtime/diagnostics/`。关闭终端、停止导航或删除 `go2-3d` 运行容器，不会删除这些宿主机文件。
本次功能只读取和保存数据，不改变运动、重试、定位接受或碰撞检查规则。

## 最常用的命令

在机器狗项目目录执行：

```bash
cd ~/go2_nav

# 列出保存的故障
bash go2_3d/tools.sh faults

# 查看最近一次真实故障的中文报告
bash go2_3d/tools.sh fault-show latest

# 导出这次故障的诊断包
bash go2_3d/tools.sh fault-export latest
```

`fault-export` 会打印 `.tar.gz` 文件的实际路径。把这个文件复制到电脑、提供给后续分析，
通常比复制一大段终端文字更完整。查看和导出不需要 ROS、Docker 正在运行，也不会重试路线或启用运动。

查看指定历史故障时，把 `faults` 输出的 ID 原样填入：

```bash
bash go2_3d/tools.sh fault-show ID
bash go2_3d/tools.sh fault-export ID
bash go2_3d/tools.sh fault-sessions
```

`latest` 优先选择真实故障，较新的空闲会话、人工停止或手工快照不会盖住它。
列表及报告优先显示北京时间，并保留 UTC 原值便于对齐原始日志。

## 故障包里有什么

- 最初触发的原始消息、来源节点、源时间戳和接收时间；后续重试、ABORTED、成功、暂停、取消按时间线保留。
- 故障前约 20 秒的有界原始事件，以及触发后的约 5 秒；连续错误可延长后段到最多 20 秒。
  更晚的结果会补入单独上下文窗口，不伪装成完整连续记录。
- 控制器 `/cmd_vel_nav`、平滑后的 `/cmd_vel`、实际 `/odom`，包括幅值、正反切换、位移和转角。
- 定位有效性及状态、运动桥状态、Nav2 启动状态、NavigateToPose action 状态、当前路径和航点信息。
- 最新 TF 的数值、时间和缺失/过期状态；小范围局部代价地图原始单元及其几何信息。
- 相关节点 `/rosout`，以及宿主机捕获的原始启动/运行 stdout、stderr。故障附近的日志片段单独冻结，
  后续轮转不会把它从故障包里抹掉。
- 可用的 Nav2 生命周期、关键运行参数、发布/订阅端点；缺少服务或消息时明确写“不可用”。
- 启动参数、源码提交号和本地修改标记、实际 Docker 镜像 ID、选定地图的元数据，以及当时可读取的配置副本。

规划失败、控制进度超时、坐标变换错误、定位丢失、启动/进程退出、目标拒绝等会触发记录。
同一段连续重试会合并为一个事件，保留最初证据并补充结果；人工停止与自动故障分开标记。
宿主机还观察异常的 ROS 子进程死亡，即使诊断节点本身退出，仍尽量留下退出行与运行日志。

## 如何理解“停车原因”

报告中的“观察到的触发”是实际收到的错误，不是猜测出的唯一物理根因。
例如 `Failed to make progress` 表示进度检查超时，不能单凭它认定底盘坏了、定位错了或前方没有障碍。

比较同一时间窗里的两路命令、真实位移、桥状态、TF 和局部地图，才能继续区分：
控制器没有发前进、平滑后的指令不同、桥拒绝指令、有命令但实际位移不足、或实时障碍限制了运动。
过期/缺失数据不能当成正常，零位移观察也不会自动修改控制参数。

## 存储和采集边界

会话结构如下，实际文件按可用证据生成：

```text
runtime/diagnostics/<会话 ID>/
  manifest.json                 源码、镜像、启动、地图和采集状态
  launch.log、launch.log.*       轮转的原始终端日志
  summaries.jsonl*              轮转的控制摘要
  context/                      有界的配置和地图元数据副本
  faults/<故障 ID>/
    report.txt                  中文报告
    summary.json                故障和最新现场摘要
    evidence.json               初始证据、前后事件、时间线与覆盖情况
    launch-before.log.gz        故障前日志片段
    launch-after.log.gz         后续补充的日志片段
runtime/diagnostics/exports/     导出的诊断包
```

原始终端日志最多保留 5 × 8MiB；事件、路径、局部栅格、队列都有大小限制。
会话保留目标为 64MiB，全目录目标为 512MiB、100 个会话、200 个故障；导出区也参与清理。
清理只管理本功能标记的旧记录，优先保护活跃会话和最新故障。受保护数据超出目标时会明确报告超额，
而不是删除正在记录的故障。因此这些数值是保留目标，不是任何情况下都强制成立的磁盘硬上限。
需要长期保留的诊断包请复制到电脑或此自动清理目录之外。

写盘在有界后台队列中执行。磁盘不足、写入失败、队列丢弃、消息过期、窗口截断、退出未刷完等情况，
会通过采集状态、日志或证据标记说明。异常断电发生在首次写入之前时，仍可能丢失尚在内存中的数据。
此功能不持续录制巨量雷达点云、相机视频或完整 PCD，不打包进程环境变量或凭据，
也不承诺复现每一个传感器输入。ROS 原生日志文件不无限复制到持久目录；保存的是轮转终端日志和有界 ROSout 证据。

更新仓库并重新启动导航后生效；此前没有采集的数据无法补录。日常启动命令保持不变。
