# 定位心跳与完整地图显示发布的隔离

2026-11-13 的故障摘要首先记录到诊断订阅者心跳超时，随后包含
`Path alignment robot TF is stale or future-dated`，TF 年龄约 0.302–0.402 秒。
后续窗口的运动桥报告 `odometry_timeout`，导航 action 为 `CANCELED`，13 个目标保留。
摘要包含人工恢复后的独立窗口，不能用最新状态反推第一次停车原因。
现场唯一根因仍需导出包的 `initial_snapshot`、事件窗口和原始启动日志确认。

代码审查发现，mapper 原先在同一互斥回调组执行定位心跳、TF 更新和完整地图发布。
dense 配置每 3 秒把全量地图转换为 PointCloud2 并发布；这与 GICP 配准是否正常无关。
云端 Humble 合成实验使用 5,077,530 个点（60,930,360 字节 XYZ payload），没有订阅者，
也复现了 0.643、0.715 秒的心跳/TF 定时器间隔，对应地图回调耗时 0.641、0.712 秒。
这证明该显示接口能够阻塞更新，超过现有时效保护；它不是实机首停原因的完整证明。

## 改动

`stack.launch.py` 在 localization/navigation 模式关闭 mapper 内的地图显示发布，
由独立的 `go2_saved_map_cloud` 进程读取同一 `/runtime/navigation_map/map.pcd`。
新进程只在启动时打包完整点云，此后按原配置周期发布缓存内容。
显示消息仍使用当前发布时间、原坐标系、完整 XYZ 数据和 reliable/transient-local depth=1 QoS。
传感器、路径、定位 TF 的时间戳不变。标准配置 2 秒、dense 配置 3 秒的发布周期保留。

建图模式仍沿用原发布路径。保存地图、点数、密度、地面、GICP 配准、传感器时效阈值、
控制器、障碍检查和运动授权规则均不变。修复作用于每次选中的保存地图，不含具体地图名或坐标分支。
独立进程避免显示发布占用 mapper 的回调组和 Python GIL，但不保证整机负载下的硬实时性。

## 经用户确认的有限定位接续

用户另行要求优先持续巡检，并确认“允许短暂定位更新抖动，使用仍然新鲜的里程计接续；
持续失效仍停车，目标保留”。因此把已接受 GICP 后的接续预算从 3 秒／1 米／60°
调整为 **5 秒／1.5 米／90°**，时间、累计位移、累计转角任一上限到达后仍失效停车。
来回移动或反向转动不能补回预算；被拒绝的扫描不会刷新最后接受时间或伪装为匹配成功。
启动、人工重定位、无已接受位姿时不能开始接续；接受新的有效 GICP 后才重新计量预算。

该接续仍要求真实里程计不超过 0.3 秒、点云不超过 1 秒；定位心跳和控制器 TF 的
时效保护不放宽。障碍检查、人工停止/取消、失败目标保留规则继续生效。
这是按巡检连续性要求选择的有限预算，允许短时间内更多里程计误差积累，
不是上述 `odometry_timeout` 的修复，也不保证所有低特征场景都能继续导航。

## 更新

已安装自定义导航插件的当前版本，只需停止本次导航、更新仓库再用原命令启动；
本补丁为挂载源码中的 Python/launch 修改，没有新增镜像依赖或 C++ 插件更新。

```bash
cd ~/go2_nav
git pull --ff-only
bash go2_3d/tools.sh use-map farm12
bash go2_3d/run.sh navigation dense 0 0 0
```

这里的 farm12 仅为操作示例，换图仍使用相同入口。
若还停车，导出已有故障即可，无需先重复恢复来制造更多故障：

```bash
bash go2_3d/tools.sh fault-show latest
bash go2_3d/tools.sh fault-export latest
```

传递导出的 `.tar.gz` 才能保留首次触发前后数据；终端摘要只展示部分证据。

## 验证范围

ROS 回归覆盖三种启动模式、标准/dense 配置、两个保存地图的全点几何与原文件不变，
以及独立显示进程阻塞时真实 Mapper 的心跳/TF 更新、扩展接续后的时间/距离/转角耗尽
及传感器失效停车。测试使用合成地图、传感器和隔离 DDS。
这些是云端 x86_64 软件验证，不是农场地图、Jetson ARM64 或实机导航验收。

本次完整 5,077,530 点显示进程进行三次 0.8 秒阻塞时，真实 GICP/Mapper
持续有效，最大心跳间隔 0.212 秒、TF 间隔 0.247 秒。扩展接续回归确认超过旧的
3 秒、1 米、60°预算仍可保持，随后新的预算耗尽、传感器过期或人工重定位仍撤销有效性。
保持测试退出码为 0；ROS 清理阶段另有一次 `Destroyable` 提示，未出现在运行断言阶段。
