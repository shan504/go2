## 本次附件能证明什么

2026-11-13 用户提供的终端日志中，第 4 点在北京时间 10:34:08 成功，误差 0.249m。
第 5 点从 (68.17, 10.06) 前往 (91.45, 19.47)，先前进约 9m，随后停滞。
首次停车在 10:35:23.825，由 `controller_server: Failed to make progress` 触发，
到目标仍约 16.185m；后续人工恢复 6 次也都是进度失败。多数恢复约 10 秒就再次失败。
规划器仍约每秒传入路径，这份附件没有 `failed to create plan`。
这与前一次 GridBased 无路停车属于不同的触发链，增加重试次数不能修复控制停滞。

多数失败时 GICP 为 `valid=True`。两次短暂失效出现在一次进度失败之后，不能反推为最初原因。
控制器有 8 条 map→base_footprint 未来外推报错，请求时间领先最新 TF 约 0.9–66.9ms。
这 8 条都在第一次停车前；后面多次失败没有相同报错，所以不能说 TF 是反复摆动的唯一原因。
终端没有记录 `/cmd_vel` 数值、候选轨迹评分、实时障碍代价和底盘速度，
仅凭照片与这些日志无法确定实际摆动来自控制器选速、平滑/桥接、障碍代价还是底盘执行。

## 修复可复现的导航接口缺陷

Humble 官方 RotationShim 每次新路径把采样点时间设为 `clock_->now()`，
然后查询此刻到 base frame 的变换。真实 TF 常落后几十毫秒，查询默认等待 100ms 后可能失败，
恰好消耗一个 10Hz 控制周期。随后原实现会清除本轮对准状态，交回 DWB，直到下一次路径更新。
旧测试使用静态 TF，所有时间都有效，未覆盖这类动态延迟。

新的 `go2_navigation::PathAlignmentController` 继承官方 shim，显式查询最新 TF，
检查时间和有限值后，在同一坐标系计算路径朝向；不改传感器或路径时间戳。
取机器人附近的路径前视点，避免机器人已经前进后仍对准旧路径起点附近的点。
对准状态在每秒重规划之间保持迟滞；缺失、过期 TF 或不安全的旋转必须返回失败，
不能把它们当成直接前进的许可。仍复用官方旋转加速度、前视足迹碰撞检查和原 DWB。
另补当前至下个控制周期的无条件即时足迹扫掠，覆盖旋转误差进入 0.20–0.35rad
迟滞区间时官方前视检查可能提前结束的边界；障碍、未知和越界仍阻止旋转。

0.30m/s 直线、0.50rad/s 专用对准、0.30rad/s 跟踪、10 秒进度期限、到点规则、
三次有限恢复、未知空间限制以及实际碰撞几何均保留。
不修改建图、地图容量、GICP 接受参数、SLAM 后端，不针对某张地图设特殊坐标。
这个修复解决已证实的接口缺陷；实机摆动是否完全消失仍需现场验证。

## 自动保留控制证据

导航模式启动只读 `go2_navigation_diagnostics`，定期在终端和
`/navigation/control_diagnostics` 输出有界窗口摘要，失败时立即再输出一份。
它观察控制器 `/cmd_vel_nav`、平滑后 `/cmd_vel`、真实 `/odom`、定位有效性、
运动桥状态、路径与小范围局部代价地图，不发送速度、目标、启用或清图请求。
这些记录用于区分“导航没有发前进”“平滑后指令不同”“桥拒绝了命令”以及
“命令已转发但实际位移不足”，不能单凭某一项自动判定硬件故障。
不会订阅完整大地图或记录无界轨迹。
后续已增加宿主机持久保存、故障时间线与离线查看/导出，见
[故障记录说明](NAVIGATION_FAULT_RECORDS.md)。不必再依赖终端回滚复制日志。

## 更新与启动

这是新增 C++ 导航插件，首次升级需要重建导航镜像；只 `git pull` 不会把插件装进旧镜像。
旧镜像会在停止现有传感器前的预检查中给出 `build.sh` 提示。
在机器狗上停止当前导航后执行：

```bash
cd ~/go2_nav
git pull --ff-only
bash go2_3d/build.sh
bash go2_3d/tools.sh use-map farm12
bash go2_3d/run.sh navigation dense 0 0 0
```

后续日常启动仍使用原来的 use-map 和 run.sh 命令，不需要临时启动副本。
启动后运动默认关闭。已有保存路线不需要重选点；不可达点仍保留并暂停。
如果仍摆动，保留从开始摆动前直到停车后的终端日志，里面将包含新的控制摘要与对准阶段信息。

## 本次实际验证与限制

- 168 项 Python 单元测试通过，包括有界诊断、速度反向统计和无效数据处理。
- 新插件实际编译、安装与 pluginlib 加载通过；缺少插件的旧镜像预检查会拒绝启动。
- 动态 TF 延迟 10/50/100ms 的回归复现旧接口提前退出对准；新接口完成左右 126°/179°
  对准、1Hz 重规划和行走交接，缺失/过期/非有限 TF 仍拒绝运动。
- 先复现并修复 ±0.25rad 迟滞区间足迹漏检；当前足迹自由、仅下一周期足迹碰到单个
  障碍/未知单元时，两种转向均被拦截。
- 加载真实 DWB 的 9 个合成场景（直线/曲线/大角度起步 × 三种 TF 延迟）均连续前进
  超过 3.11m，开始行走后无停止；非恒等 map→odom、odom 局部地图、实际生成配置和
  每秒重规划均覆盖。障碍和未知区域仍禁止平移。
- 三次有限恢复、停止/取消/定位暂停、只读诊断、普通启动参数、三模式 launch 和
  6 项 RTAB launch 检查通过。ROS 诊断测试核实失败时立即输出且不发送控制请求。

上述为云端 x86_64 软件和合成运动验证，没有重放现场 rosbag、运行现场农场地图、
测试 ARM64 私有 SDK 镜像或执行实机运动。合成运动未包含真实步态与所有底盘动力学。
不能将其描述为实机反复摆动的全部根因已经确认或现场效果已验收。
